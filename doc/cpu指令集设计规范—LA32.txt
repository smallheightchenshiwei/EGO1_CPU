项目名称：基于 LoongArch LA32 指令集的 32 位五级流水线 CPU 设计

一、项目基本信息

CPU 位宽：32 位
指令长度：32 位定长指令
通用寄存器数量：32 个
流水线结构：五级流水线
流水线阶段：IF、ID、EX、MEM、WB
计划实现指令数量：24 条（候选子集，待核对）
开发板：EGO1
FPGA 型号：XC7A35TCSG324-1
开发工具：Vivado 2019
硬件描述语言：Verilog-2001

本项目以 LoongArch LA32 指令集为基础，选择其中一部分常用指令实现课程设计要求，不追求完整实现整个 LoongArch 指令集。

二、指令集与指令格式

本项目采用 LoongArch LA32 的真实指令编码和语义，不使用自定义的 R 型、I 型、B 型、J 型、U 型编码体系。

LoongArch 指令长度固定为 32 位，主要指令格式包括：

2R 格式
3R 格式
4R 格式
2RI8 格式
2RI12 格式
2RI14 格式
2RI16 格式
1RI21 格式
I26 格式

各条指令的具体字段位置、操作码和立即数生成规则，以 LoongArch 官方参考手册为准，后续建立完整的指令编码表。

三、寄存器设计

CPU 内部设置 32 个 32 位通用寄存器。

r0：恒为 0，不允许写入有效数据。
r1：作为 BL 等指令使用的链接寄存器。
r2 至 r31：通用寄存器。

其中，r3 在常见 LoongArch ABI 约定中作为栈指针（sp）。寄存器堆硬件仍保留 r1 至 r31 的通用读写能力，不因 ABI 约定而限制寄存器用途。

寄存器堆采用双读端口、单写端口结构。

四、流水线结构

本项目采用经典五级流水线结构。

1. IF（Instruction Fetch，取指）

根据 PC 地址从指令存储器中读取当前指令，同时生成下一条指令地址。

2. ID（Instruction Decode，译码）

对指令进行译码，识别指令类型、读取源寄存器，并生成后续流水级所需的控制信号和立即数。

3. EX（Execute，执行）

完成算术运算、逻辑运算、移位运算、地址计算以及分支条件判断等操作。

4. MEM（Memory Access，访存）

根据指令类型访问数据存储器，完成 LD.W、ST.W 等访存操作。

5. WB（Write Back，写回）

将运算结果或数据存储器读取的数据写回寄存器堆。

六、项目成员分工

本项目由 A、B 两名成员共同完成。项目采用指令类别划分的方式进行分工，不按照 CPU 的基本设计过程或流水线阶段进行划分。两名成员的工作量尽量保持均衡。

1. 共同完成的基本设计工作

A、B 两名成员都必须至少独立完成一个单周期 CPU 的设计工作，掌握单周期 CPU 的整体设计方法和工作原理。

两名成员共同参与 CPU 总体架构设计、指令集规范制定、寄存器堆设计、数据通路设计、控制信号设计、流水线结构设计、冒险处理机制设计以及顶层模块集成。

在单周期 CPU 的基础上，两名成员共同完成五级流水线 CPU 的设计与完善。

双方均需要理解 CPU 从取指、译码、执行、访存到写回的完整工作过程，不得将基本设计过程按照流水线阶段或功能模块简单拆分。

4. 双方协作与答辩要求

A、B 两名成员需要共同完成指令集核对、CPU 总体设计、五级流水线搭建、数据冒险与控制冒险处理、暂停与冲刷机制、顶层模块集成、整体仿真、FPGA 下载测试及项目文档编写。

双方需要相互检查和理解对方负责的指令及优化设计，熟悉所有模块之间的连接关系和 CPU 的完整工作流程。

课程设计验收采用针对每位成员单独提问的方式。因此，每位成员必须清楚整个 CPU 的设计原理、数据通路、控制流程、指令执行过程和优化机制，不能只了解自己负责的部分。

答辩自述时，每位成员都需要介绍 CPU 的总体设计，并重点说明自己主导完成的指令设计、功能实现、优化方法以及实验验证结果。

A 重点介绍自己负责的 12 条指令和数据前递优化工作；B 重点介绍自己负责的 12 条指令和分支控制或除法器优化工作。

双方都必须能够回答关于整个 CPU 设计的相关问题。

七、性能优化与实验要求

本项目不仅需要实现基本指令功能，还需要通过实际实验验证性能优化效果。

计划重点研究以下内容：

1. 数据前递机制：减少流水线数据相关造成的停顿。
2. 分支控制优化：降低分支指令对流水线执行效率的影响。
3. 除法器设计优化：改善除法指令的执行效率。

实验中需要记录优化前后的执行周期数、功能正确性及相关硬件资源占用情况，以数据说明优化是否有效。
